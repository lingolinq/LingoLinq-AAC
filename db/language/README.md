# db/language/ -- Multilingual Language Layer, Phase 1 committed inputs

This directory holds the versioned, committed dataset that every Phase 1 (EN schema-2 migration)
plan builds on. Nothing here existed in the repo before Phase 1 Plan 01 -- it is generated (and
regenerated) by `rake language:snapshot` and is otherwise never hand-edited.

## Files (per locale, currently `en/` only)

| File | What it is | Source |
|------|------------|--------|
| `en/rules-en.upstream.json` | The raw upstream OpenAAC-format `rules-en` file, pinned verbatim in git. The ONLY authoritative source of the `tests[]` parity fixtures AND the `substitutions` block (which nests `contractions`/`default_contractions`). Carries the upstream `_license` field verbatim. | Fetched once from `https://tools.openaac.org/inflections/rules-en.json` (see Provenance below). |
| `en/words-en.snapshot.json` | Every live EN `WordData` row, keyed by word, with `types`, `inflection_overrides`, `antonyms` only. | Live `WordData` table, via `rake language:snapshot`. |
| `en/rules-en.snapshot.json` | `rules` + `inflection_locations` (from the live `rules/en` `Setting`) merged with `substitutions` + `tests[]` + `_license` (from the pinned upstream file, verbatim). | Live `Setting.get('rules/en')` + `en/rules-en.upstream.json`, via `rake language:snapshot`. |
| `en/inflection-locations-golden.json` | `word -> WordData.inflection_locations_for([word], 'en')` output, captured from the CURRENT (pre-migration) code, over the full EN word corpus. The before-baseline for flag-off regression (Plans 03/05) and the compass-slot ground truth for schema-2 parity (Plan 05). | Live DB + the unmodified `WordData.inflection_locations_for`, via `rake language:snapshot`. |

## Why rules/inflection_locations and substitutions/tests come from different sources

`WordData.ingest` (`app/models/word_data.rb:106`) writes only
`json.slice('rules', 'inflection_locations', 'contractions', 'default_contractions')` into the
`rules/#{locale}` `Setting`. The live upstream OpenAAC `rules-en` file has NO top-level
`contractions`/`default_contractions`/`tests` keys -- its real top-level keys are `_locale,
_version, _license, _type, rules, inflection_locations, substitutions, tests`, and the contraction
maps live NESTED under `substitutions` (`substitutions.contractions`,
`substitutions.default_contractions`). So the `slice` grabs top-level `contractions` /
`default_contractions` that do not exist upstream, and drops `substitutions`/`tests` entirely.
Consequently the live `rules/en` `Setting` NEVER carries `substitutions`, `tests`, or `_license` --
only `rules` and `inflection_locations`. Therefore:

1. `rules` + `inflection_locations` are sourced from the LIVE `Setting` (this is what the runtime
   -- `WordData.inflection_locations_for`, `Api::WordsController#lang` -- actually reads today).
2. `substitutions`, `tests[]`, and `_license` are sourced ONLY from the pinned upstream file.

Do not "fix" this by reading `substitutions`/`tests` off the Setting -- they are never there.

## Golden baseline

`inflection-locations-golden.json` is captured from the CURRENT, pre-migration
`WordData.inflection_locations_for` method -- Plan 03 (schema-2 backend read path) has not yet
touched it when this snapshot is taken. It is the ground truth that:

- Plan 03/05 flag-off regression proves is unchanged when `multilingual_grammar` is off.
- Plan 05's schema-2 compass-slot parity suite is checked against when the flag is on.

## Regeneration

Snapshots and the golden baseline are regenerated ONLY by:

```
DB_USER=scotw RAILS_ENV=development bundle exec rake language:snapshot
```

Re-running on unchanged inputs (same DB contents, same pinned upstream file) produces
byte-identical output on all three JSON files (deterministic, key-sorted serialization) -- any
`git diff` after a re-run is a real, reviewable data change, never formatting noise.

`rules-en.upstream.json` is never regenerated by this task -- it is a one-time, hand-pinned
fetch (Task 2). If the upstream host moves or changes, a human must re-fetch, re-review, and
re-pin it deliberately (updating the recorded SHA-256 here and in the spec constant).

## Privacy

`words-en.snapshot.json` intentionally excludes `reviews` and reviewer identifiers (keyed by
reviewer USER global_id -- identifying internal account data). Only `types`, `inflection_overrides`,
and `antonyms` are written per word. WordData holds word/inflection metadata only; no student,
patient, board, or account content is present in any file in this directory.
