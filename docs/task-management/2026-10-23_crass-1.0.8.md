# crass 1.0.8 (GHSA-pq4g-8rxf-4g29)

**Trigger.** `security-scan` went red on PR #1167 after a merge of `develop`. The cause was not the PR: `bundle-audit check --update` cloned ruby-advisory-db at `03da937` (2026-10-23 18:23 UTC); the GHSA-pq4g-8rxf-4g29 entry for `crass` had reached master two minutes earlier in `0607c14` (rubysec PR #1269). `develop`'s security-scan passed at 16:20 UTC on `77fc7d3`, before the advisory landed, failed at the bundle-audit step at 19:10 UTC on `34659d2`, and passed again on `359b709` after #1183 merged.

**Reach.** `crass` is the CSS tokenizer under `loofah` and `sanitize`. `Processable#process_html` (`app/models/concerns/processable.rb:126-128`) runs `Sanitize.fragment(html, Sanitize::Config::RELAXED)`, and RELAXED allows `<style>` and `style` attributes, so the advisory applies. Callers: `UserGoal` descriptions and `UserIntegration`. `lib/svg_sanitizer.rb` uses Loofah but never calls Crass.

**Red/green.** Probe and spec, same inputs:
- 1.0.7 (`develop` lock): `<style>url(x y\\) {} @import "..."` keeps the `@import`; a `style` attribute keeps `url(javascript:...)`. The new example at `spec/models/concerns/processable_spec.rb:52` fails.
- 1.0.8: both are stripped; `processable_spec.rb` 29 examples, 0 failures.

**Change.** `Gemfile` floor `>= 1.0.8`, `Gemfile.lock` 1.0.8 via `bundle update crass --conservative` (no other gem moved). `bundle-audit` clean against the same advisory db.

**Not in scope, noted for follow-up.** RELAXED still allows `position: fixed` overlays, page-global `<style>` rules, and remote loads (CSS `url()` with `http`, `https` or relative URLs, and `<img src>`/`srcset`) in goal descriptions, which render through `htmlSafe` in the detail views (`templates/goals/goal.hbs:244`, `:297`, `templates/user/goal.hbs:186`, `components/new-goal.hbs:36`, `:66`). Descriptions saved before this change reaches an environment are not re-sanitized: every crass release before 1.0.8 has this bug, so that is every existing row. `process_html` runs on write only.

**Corrected 2026-10-23 (follow-up PR).** The advisory-db attribution, the scan timeline, the remote-load wording and the stored-content window above were corrected after an independent review of #1183. That review also asked for positive controls in the spec example, so a config that drops `<style>` cannot pass it without reaching crass; they were added and fail under `Sanitize::Config::BASIC`.
