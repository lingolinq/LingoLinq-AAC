# crass 1.0.8 (GHSA-pq4g-8rxf-4g29)

**Trigger.** `security-scan` went red on PR #1167 after a merge of `develop`. The cause was not the PR: `bundle-audit check --update` pulled ruby-advisory-db `03da937` (2026-10-23 14:23 -0400), which added GHSA-pq4g-8rxf-4g29 for `crass` 1.0.7. `develop`'s own security-scan had passed at 16:20 UTC, before the advisory landed, so every branch fails this step from now on until `crass` is 1.0.8.

**Reach.** `crass` is the CSS tokenizer under `loofah` and `sanitize`. `Processable#process_html` (`app/models/concerns/processable.rb:126-128`) runs `Sanitize.fragment(html, Sanitize::Config::RELAXED)`, and RELAXED allows `<style>` and `style` attributes, so the advisory applies. Callers: `UserGoal` descriptions and `UserIntegration`. `lib/svg_sanitizer.rb` uses Loofah but never calls Crass.

**Red/green.** Probe and spec, same inputs:
- 1.0.7 (`develop` lock): `<style>url(x y\\) {} @import "..."` keeps the `@import`; a `style` attribute keeps `url(javascript:...)`. The new example at `spec/models/concerns/processable_spec.rb:52` fails.
- 1.0.8: both are stripped; `processable_spec.rb` 29 examples, 0 failures.

**Change.** `Gemfile` floor `>= 1.0.8`, `Gemfile.lock` 1.0.8 via `bundle update crass --conservative` (no other gem moved). `bundle-audit` clean against the same advisory db.

**Not in scope, noted for follow-up.** RELAXED still allows `position: fixed` overlays, `https` `url()` loads and page-global `<style>` rules in goal descriptions, which render through `htmlSafe`; content stored under 1.0.7 is not re-sanitized.
