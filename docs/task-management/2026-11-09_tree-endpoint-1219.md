## Diagnosis

1. **Response size (Cloud Run 32 MiB cap, mode 1): driven by inline `data:` pictures in `image_urls`.** Local
   boards carry them because the seed ran with uploads off (known; offline-boards task log, HANDOFF section 6).
   Production board JSON carries short CDN links (`lingolinq/quick-core-60`: 60 of 60 `image_urls` on
   `d34sa6lc5jfe66.cloudfront.net`, anonymous GET, 2026-11-09). So the cap is most likely hit only where boards
   hold inline pictures: local, and probably the dev/staging database (the September repro was on dev).
   NOT verified on dev, staging or production: `/tree` needs a signed-in token there (anonymous GET: 400
   "Access token required"), and this machine has no such account.
2. **Slowness (Rack::Timeout, mode 2): real on every environment.** `images_and_sounds_for` runs once per board,
   uncached: `lib/json_api/board.rb:243-244` calls it without the `as_lite` gate its neighbours have;
   `app/models/board.rb:2533` reads a cache that is never written (`set_cached` commented out at `:2561`).
   145 lookups, 312 queries, 5.5 s on an idle local server. Under concurrency it passes the 15 s Rack::Timeout and
   starves other requests on a one-instance service (dev, staging: maxScale 1 per the September log).
3. **Offline impact: indirect.** `/tree` is not part of the offline sync. Callers: Modern board page background
   warm (`routes/user/board-detail.js:160, 198`, `routes/user/board-alt.js:59`, via
   `board_detail_cache.warm_full_tree_if_root_only`), the guided tour (`components/guided-tour.js:955`). Its data goes
   to the in-memory cache and Ember store only (`utils/board_detail_cache.js:185-192`), never to the device. A failure
   makes Modern folder taps cold and feeds #1034's wrong "saved for offline" message; a slow `/tree` also takes server
   threads from sync requests.

## The issue's suggested fix 1 is unsafe as written

Gating `images_and_sounds_for` on `as_lite` and using `board.settings['image_urls']` instead would serve licensed
(protected) symbol links to users without the licence: the stored list is what the saving client sent
(`app/models/board.rb:2088`), and only the lookup swaps a protected image for its fallback when the viewer lacks the
source (`lib/json_api/image.rb:19-25`; the loop then writes that URL into `image_urls`, `json/board.rb:288`).
CONFIRMED by reading; not tested.

## Candidate fixes (not chosen; /fix-proposal applies)

- **A. One lookup for the whole tree:** collect the ButtonImage ids of root plus descendants, load them in one query,
  apply the same protected-source fallback per image, then serialize each board from that map. Keeps licensing
  behaviour; removes the per-board queries. Medium change in `#tree` and `JsonApi::Board`.
- **B. Cache per board, not per user:** the model's own TODO (`board.rb:2524-2530`): cache both protected and
  fallback URLs keyed on the board's update stamp, choose per viewer in process. Helps every endpoint, larger change,
  cache size was why it was turned off ("fills up half the cache").
- **C. Size:** only if real data can pass 32 MiB: stream or paginate descendants. Not needed if (1) holds.
- Regression guards either way: a query-count assertion on `#tree` for N boards, and a response-size assertion.
