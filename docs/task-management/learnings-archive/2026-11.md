# Learnings archive — 2026-11

## 2026-11-02: unanchored report-name matches steal allowlisted prefixes

- **A substring match on `params['report']` that sits before a prefix branch will run for every
  allowlisted `status-` / `access-` / `device-` / `vocab-` / `grid-` name that contains that
  substring.** `match(/home_boards/)` ran the system-wide home-board census for
  `status-home_boards`. Exact equality keeps the prefix branch. A test that only asserts the leaked
  key is absent still passes if a single connection is dropped by `count <= 1`; seed two.
  Cite `admin_reports` in `app/controllers/api/organizations_controller.rb`.

## 2026-11-02: `^` is a line anchor in Ruby; allowlists need `\A`

- **`'home_boards\nstatus-x'.match(/^status-/)` is truthy**, so a `^`-anchored allowlist lets any
  value through once a line break and an allowed prefix are appended. Use `\A` (and `\z` for a full
  match) on every request-param allowlist, and test a line-break value. Also guard the param type:
  `report[]=x` turns `.match` into a 500. Cite `admin_reports` in
  `app/controllers/api/organizations_controller.rb`.

## 2026-11-02: org-report CSV is an Ember sink, not a Rails one

- **A JSON report that an Ember action turns into `data:text/csv` via
  `columns.join(',')` is a spreadsheet-injection sink even when Rails never
  writes a CSV.** Quote every cell, prefix `'` on a leading `= + - @` tab or CR,
  and do it for every column in that join (name, email, referrer, stats keys),
  not only the field named in the issue. Storage sanitizing is a different
  change: it mutates attribution for every consumer. Cite
  `download_list` in `app/frontend/app/controllers/organization/reports.js`.

## 2026-11-03: the OWASP formula-starter list includes LF and full-width characters

- **A CSV formula guard keyed on `= + - @` (and tab/CR) still misses LF and the full-width
  `＝ ＋ － ＠`, which OWASP's CSV Injection page now lists.** Keep the list in one constant and test
  each entry. Guard by `String(value)`, not only for strings: request params can arrive as arrays.
  Cite `app/frontend/app/utils/csv.js`.

## Board language has one rule: `session_board_locale` (2026-11-06)

**Surface:** `utils/board_display_locale.js`, used by board-detail, board-alt and the legacy board route.

Switch Languages applies where the board has that language; otherwise the board speaks its own. Basic and
legacy used to obey the plain `label_locale`/`vocalization_locale` stash too, and Home writes that, so any
board storing English reopened in English. Do not add a plain stash write to fix a language bug: routes
ignore it without an override, and with one it beats the override. `home_board.locale` is not a reliable
preference to honour on boards, because `app-state.js:1474` copies the viewed language onto it; the
supervisee `locale` still starts from it because it is only a default the creator sees and can change. Boards with no locale
(`obf/stars`, `integrations`) must stay undefined so readers fall back to the UI language.

To ask whether a device can speak a language, use `speecher.has_voice_for`: `find_voice_by_uri` falls back to
a voice in another language, so a list or cloud check says yes when speech comes out in the wrong voice. An `ember test --filter` regex alternation can silently skip describe-style
tests: check the test names ran before trusting a green or a surviving mutant.

**First seen in:** `2026-11-06_create-board-language-speech.md`.

Do not add a class property named `speech` to create-board-new. `init` sets it only where
`webkitSpeechRecognition` exists and `willDestroy` clears `speech.ready`, so pointing it at speecher
silenced every board in other browsers until a reload. `@selection` on ModernSelect writes back before
the action runs, so bind `{{readonly ...}}` when the action needs the old value, and test a select by
clicking a real option: `send()` skips that write.

- A route `setupController` test leaves its stand-in controller on `editManager` and `contentGrabbers`, and the
  failure shows up in unrelated later tests as `board.contextualized_buttons is not a function`. Restore both in
  `finally`, and run a new route test alongside `app_state` before trusting it: a targeted filter hides this.
- `op run` resolves every `op://` value already in the environment, not only the ones in its env file. Load local
  test settings inside the command, or Rails stops at boot with `bad decrypt`.
- Before acting on a reported data exposure, check whether the same caller can already read that value by the normal
  route. The language on supervisee rows looked like a leak; `GET /users/:id` already returned it.
