# Learnings archive — 2026-11

## 2026-11-06: org email-template overrides only ride `load_domains`, not `host_settings`

- **`Organization.load_domains` copies `host_settings`, then a three-line special case copies
  `settings['email_templates']` onto the same host hash.** Specs that assert `app_name` after
  `set_domain_id` stay green if that copy is deleted; the override never reaches
  `SystemEmailTemplates.lookup` or `SystemEmailOverride#mail`. Cover it by storing a distinctive
  `html_body` and `text_body`, `set_host`, enqueue, `Worker.process_queues`, and asserting both
  MIME parts. Cite `Organization.load_domains` and issue #912.

## 2026-11-06: `load_domain("default")` does not reset `current_host`

- **`JsonApi::Json.set_host` writes `@@running_hosts[Worker.thread_id]`. `load_domain("default")`
  only reloads domain settings.** A mailer example that `set_host`s a custom domain and then
  teardowns with `load_domain` leaves later examples on that host. Assertions that interpolate
  `JsonApi::Json.current_host` into the expected URL (lesson_assigned) stay green. Restore the
  previous host in `after` (or `ensure`), and assert the leaked host is gone. Cite
  `spec/mailers/user_mailer_spec.rb` and `lib/json_api/json.rb`.

## 2026-11-06: attestation harness `cd` uses the caller's cwd, not the script path

- **`cd "$(git rev-parse --show-toplevel)"` runs in the current directory, not beside
  `$0`.** Spawning the inner harness as `bash /tmp/.../attestation-hash-guard-test.sh`
  from the live checkout still cds to the live tree and edits live `docs/legal/`.
  `cd` into the throwaway worktree before the inner bash. The isolation test is
  chmod a-w on the live legal files, then run the harness. Cite issue #777.

## 2026-11-02: unanchored report-name matches steal allowlisted prefixes

- **A substring match on `params['report']` that sits before a prefix branch will run for every
  allowlisted `status-` / `access-` / `device-` / `vocab-` / `grid-` name that contains that
  substring.** `match(/home_boards/)` ran the system-wide home-board census for
  `status-home_boards`. Exact equality keeps the prefix branch. A test that only asserts the leaked
  key is absent still passes if a single connection is dropped by `count <= 1`; seed two.
  Cite `admin_reports` in `app/controllers/api/organizations_controller.rb`.

## 2026-11-02: `^` is a line anchor in Ruby; allowlists need `\A`

- **`'home_boards\nstatus-x'.match(/^status-/)` is truthy**, so a `^`-anchored allowlist lets any
  value through once a line break and an allowed prefix are appended. Use `\A` (and `\z` for a full
  match) on every request-param allowlist, and test a line-break value. Also guard the param type:
  `report[]=x` turns `.match` into a 500. Cite `admin_reports` in
  `app/controllers/api/organizations_controller.rb`.

## 2026-11-02: org-report CSV is an Ember sink, not a Rails one

- **A JSON report that an Ember action turns into `data:text/csv` via
  `columns.join(',')` is a spreadsheet-injection sink even when Rails never
  writes a CSV.** Quote every cell, prefix `'` on a leading `= + - @` tab or CR,
  and do it for every column in that join (name, email, referrer, stats keys),
  not only the field named in the issue. Storage sanitizing is a different
  change: it mutates attribution for every consumer. Cite
  `download_list` in `app/frontend/app/controllers/organization/reports.js`.

## 2026-11-06: an open-AND-closed status check is dead; `created_ids` is the load-bearing form

- **`status == ASSIGNABLE_STATUS && status in SCOT_OWNED_CLOSED` can never fire**, because
  `ASSIGNABLE_STATUS` is `'open'`. Mutating `ASSIGNABLE_STATUS` to `'verified-closed'` makes that
  dead conjunction accidentally true, so it is the wrong red test for `audit-merge.rb`. Force the
  appended record to a Scot-owned status (or a non-untriaged disposition) after `findings << record`,
  and abort the mutation setup unless that needle occurs once. Scope the invariant to `created_ids`,
  not `firstSeen == run_date`, or a same-day out-of-band close becomes a false-positive abort.
  Cite `scripts/audit-merge.rb` (lockstep with `scripts/promote-finding.rb`).

## 2026-11-03: the OWASP formula-starter list includes LF and full-width characters

- **A CSV formula guard keyed on `= + - @` (and tab/CR) still misses LF and the full-width
  `＝ ＋ － ＠`, which OWASP's CSV Injection page now lists.** Keep the list in one constant and test
  each entry. Guard by `String(value)`, not only for strings: request params can arrive as arrays.
  Cite `app/frontend/app/utils/csv.js`.

## Board language has one rule: `session_board_locale` (2026-11-06)

**Surface:** `utils/board_display_locale.js`, used by board-detail, board-alt and the legacy board route.

Switch Languages applies where the board has that language; otherwise the board speaks its own. Basic and
legacy used to obey the plain `label_locale`/`vocalization_locale` stash too, and Home writes that, so any
board storing English reopened in English. Do not add a plain stash write to fix a language bug: routes
ignore it without an override, and with one it beats the override. `home_board.locale` is not a reliable
preference to honour on boards, because `app-state.js:1474` copies the viewed language onto it; the
supervisee `locale` still starts from it because it is only a default the creator sees and can change. Boards with no locale
(`obf/stars`, `integrations`) must stay undefined so readers fall back to the UI language.

To ask whether a device can speak a language, use `speecher.has_voice_for`: `find_voice_by_uri` falls back to
a voice in another language, so a list or cloud check says yes when speech comes out in the wrong voice. An `ember test --filter` regex alternation can silently skip describe-style
tests: check the test names ran before trusting a green or a surviving mutant.

**First seen in:** `2026-11-06_create-board-language-speech.md`.

Do not add a class property named `speech` to create-board-new. `init` sets it only where
`webkitSpeechRecognition` exists and `willDestroy` clears `speech.ready`, so pointing it at speecher
silenced every board in other browsers until a reload. `@selection` on ModernSelect writes back before
the action runs, so bind `{{readonly ...}}` when the action needs the old value, and test a select by
clicking a real option: `send()` skips that write.

- A route `setupController` test leaves its stand-in controller on `editManager` and `contentGrabbers`, and the
  failure shows up in unrelated later tests as `board.contextualized_buttons is not a function`. Restore both in
  `finally`, and run a new route test alongside the speak mode tests (`/board language rule|speak/i`) before trusting
  it: a targeted filter hides this.
- A local `ember test` passes a test that ends with a fetch queued, with only a `[queued-fetch]` warning. CI's
  `--query "timingStrict=1"` fails it, so run new tests that open a dialog with that query.
- `op run` resolves every `op://` value already in the environment, not only the ones in its env file. Load local
  test settings inside the command, or Rails stops at boot with `bad decrypt`.
- Before acting on a reported data exposure, check whether the same caller can already read that value by the normal
  route. The language on supervisee rows looked like a leak; `GET /users/:id` already returned it.

## A row's permission fields can mean two different people (2026-11-07)

In `JsonApi::User`'s supervisor branch, `edit_permission` and `modeling_only` label the listed supervisor's
link (the Supervision page shows them that way), while `can_set_goals` and the goal fields decide what the
person asking may see. On your own caseload those are the same person, so a fix that swapped one for the other
looked safe and would have mislabelled every row a manager sees on a therapist's Supervision page. Before
changing who a field describes, find each screen that reads it for a user other than the signed-in one.
Source: `lib/json_api/user.rb` (`goal_viewer`), `app/frontend/app/components/supervision-settings.hbs`.

## Two kinds of "modeling only" overlap, and a carve-out must handle both (2026-11-07)

`modeling_only_for?` answers true at once for a supporter whose billing lapsed, before it looks at the link.
A rule that meant "keep a lapsed supporter, still exclude a modeling-only LINK" and was written as
`modeling_only_for? && !modeling_only?` therefore dropped the link check for exactly the lapsed supporters,
and they kept set_goals, goal-linked notes and badge edits on a modeling-only link. Ask the per-link question
directly (`link_modeling_only_for?`) and test the overlap: lapsed billing plus a modeling-only link.
Source: `app/models/concerns/supervising.rb`, `app/models/user.rb` set_goals rule.

## 2026-11-06: reading PR content in a pull_request_target job

- **Diff two blob ids, not two commits with a path, when the content is untrusted.** In the
  data-bearing gate's `pull_request_target` checkout, a path-based `git diff` reads develop's
  `.gitattributes` from the work tree, so an attribute can turn a text file into "Binary files
  differ" and hide its lines. `git diff -U0 --no-ext-diff --no-textconv <old-blob> <new-blob>`
  has no path, reads no attributes and runs no driver. Cite `scripts/data-bearing-path-check.sh`
  `added_lines`.
- **A mutant that survives points at a missing case, not a redundant line.** Dropping the
  identical-blob shortcut in `scan_entry` passed all 326 cases until a mode-only change (same
  blob, `chmod +x`) was added: without the shortcut an empty diff reads as "no hunk" and the
  whole file is scanned. Cite `scripts/tests/data-bearing-path-check-test.sh`
  ("a mode-only change adds no lines").

## 2026-11-08: which breach runbook is in force

- **A legal doc's filename does not say whether it is current; the register does.**
  `docs/legal/BREACH_RUNBOOK.md` reads like the canonical runbook but is a superseded, frozen
  predecessor (`DOC-d4e3b8be32`). The one in force is the register row with no `supersededBy`
  (today `docs/legal/2026-09-14_incident-response-breach-runbook.md`, `DOC-f082212111`). Before
  changing any legal doc, find its row in `audit-reports/DOCUMENT-REGISTER.json`, follow
  `supersededBy` to the end, and compare the file's sha256 to `attestedContentHash`: a match means
  the bytes are frozen and the change is a Path A successor that only Scot attests.

## 2026-11-08: offline save paths (utils persistence copy, SQLite two-statement writes)

- **The Ember Data adapter runs the UTILS persistence copy, not the service** (2026-11-08, PR #1268).
  `adapters/application.js` mixes in `persistence.DSExtend` through the `utils/persistence.js` Proxy; the
  service's DSExtend is a class static, so it is not `in` the instance and the Proxy returns the utils one, whose
  findRecord calls the module-local `store_eventually` and queue. A fix to the save queue needs both copies and a
  test on the utils module-local instance (clear `window.persistence` so the Proxy returns its target).
- **SQLite writes on the installed app are two statements, queued separately** (2026-11-08, PR #1268). Both
  bridges (`www/sqlite_bridge.js` in the mobile shell, `utils/capacitor_sqlite_shim.js`) run one statement at a
  time but enqueue each on its own, so a SELECT-then-INSERT is not atomic and the table has no unique ref_id.
  The shim's `transaction` also drops statements issued from a result callback, so do not fix with a nested
  transaction. Serialize per row (`utils/sqlite_row_queue.js`) and drive `dbman.store`/`dbman.remove` in tests,
  not `store_internal`/`remove_internal`.

## 2026-11-08: giving a page the Modern rail means asking the shell, and the strip it sits in

- **A Modern page with "no side menu" is usually missing from `showGlobalChrome`, not from its own
  template.** The rail is mounted once in the app shell; the org section was deliberately kept out
  (only a rooms-only supervisor's Rooms list got it). Opening it was one prefix test there plus a
  `globalChromeOrg` beside `globalChromeUser`, so the rail can switch rows without any page passing
  it anything. Cite `app/frontend/app/controllers/application.js` `globalChromeOrg`.
- **`.md-pillnav` only hugs its pills as a direct child of `.md-workspace`** (a flex column).
  Wrapped in any block, such as `.ch-tabs-fit`, it stretches to its 1120px max-width. `width: fit-content`
  on the variant fixes it (an overflowing strip still overflows, so `{{fit-or-select}}` keeps
  measuring correctly), but the better fix here was to render the strip in `.ll-appshell__navbar`,
  whose `.md-pillnav` rule already sets it; the variant rule was removed again.
- **Moving a nav up to the parent template strands the child's copy.** The people page kept
  Modern's own section pills after the org strip started rendering in Modern, giving two identical
  navs. Grep the child templates for the same labels when hoisting a nav.
- **To put something "where the home pill nav is", render it in `.ll-appshell__navbar`, do not
  offset it.** Every positioning rule for that nav keys on the slot (sticky offset, shell
  clearance, <=900px stacking, the `--primary` <=640px swap). Measured nudges would have had to
  match six breakpoints in two layouts. Cite `app/frontend/app/components/org-tabs.hbs`.
- **Read the layout only after the user record hydrates.** `effectiveLayout` falls back to a
  stored mirror until `preferences.dashboard_layout` arrives, so an early probe of a Focused
  account reads Gentle. Set the layout in memory (unsaved) before measuring.
- **A broad `:has()` rule can silently outweigh an older page-specific one.** The Gentle zeroing
  rule's `:has()` qualifiers made it one class heavier than `.md-shell--org-directory`'s
  clearance; exclude the page in the broad rule rather than raising the narrow one.

- **Nav position below 901px is set by `#content` padding (2026-11-08, modern-org-nav round 3).** At 900px and below the app shell's nav slot is in the normal flow, so `#content`'s top padding decides where the pill nav sits; above 900px it does not. The Focused home page has its own `#content` padding (`var(--topbar-height)`), and other pages use the base `+ 3rem`, so "same slot" did not mean "same height". When matching nav positions, measure at 900px and narrower in both layouts, not only at desktop widths.

- **Excluding a case from a shared `!important` rule: use `:where(:not(...))`, not `:not(...)` (2026-11-09, modern-org-nav review).** Each `:not(.x)` adds a class of weight, so the edited rule starts beating the rules written to override it. Here the Gentle shell-zeroing rule went from (1,5,1) to (1,7,1) and silently took 30px off Goals and Recordings and 52px off Stats. Measuring only the pages you were fixing does not catch it; compare every page the rule covers against develop. `:where()` excludes with zero weight.

## 2026-11-09: writing a Path A successor from an attested predecessor

- **Re-derive a predecessor's change summary from the diff; don't copy its banner.** The
  2026-09-14 runbook's banner listed its edits as "§2 trigger list" and "§4.3 containment step";
  a diff against the 2026-08-15 record puts them in §1 and §4.2 step 5. Carrying the banner
  forward would have republished the wrong locators. Run `diff <older> <predecessor>`, map each
  hunk to its heading, then write the history entry.
- **A banner that states its own status goes false when it is attested.** "DRAFT - NOT YET
  ATTESTED" sat in the 2026-09-14 runbook's attested bytes. Point at the register row instead of
  stating status in the file, so the successor stays true after the attestation lands. Cite
  `docs/legal/2026-11-09_incident-response-breach-runbook.md` header.

## 2026-11-10: direct picture requests and where a server setting reaches the apps

- **Staging is not a precedent for production CDN addresses** (2026-11-10, PR #1268). Staging and dev have no
  `UPLOADS_S3_CDN`, so uploads there are on the bucket host and button-set addresses are relative
  (`app/models/board_downstream_button_set.rb:326`, `:391`). A change to how a production CDN address is fetched
  has no staging run behind it; say so, and keep file kinds that were never tried on their old route.
- **A server setting reaches the mobile apps through `/api/v1/domain_settings`, not `globals.js.erb`** (2026-11-10).
  `extras:mobile` writes the live answer into the app (`lib/tasks/extras.rake:730`); the bundle the apps copy does
  not include globals (`app/assets/javascripts/application.js:1-5`). A fact sheet line about "the only route" to
  another platform is a cross-file claim: check it before rejecting an option on it.
- **`cors_match` includes the trust result** (`app/frontend/app/services/persistence.js:1551`), so a test that only
  checks "the request went direct" also passes when a host was wrongly added to the trusted list. Pair it with a
  test that a forced sync still downloads a changeable file on that host.

## 2026-11-10: the app shell's navigation fallback, and testing the real worker

- **A navigation request reaches a service worker with redirect mode `manual`** (2026-11-10, PR #1268). `fetch(event.request)`
  answers a same-origin 302 with an opaque redirect: status 0, `ok` false. A fallback written as `!response.ok`
  would replace every renamed board or user link with the cached page. Branch on `status >= 500` (plus 429 for
  the request limiter), and keep a redirect e2e case (`app/frontend/e2e/offline-launch.spec.js`, "a redirect").
- **A worker time limit cannot tell a hung network from a slow working server.** The cached page it answers
  runs the app version the device holds, with the environment keys frozen at cache time and without the page's
  extra scripts (the shell has no chart scripts). Record those as known limits whenever a limit is added, and
  measure which reason answered the cache after release. The limit was removed on 2026-11-05 for this reason,
  put back on 2026-11-10 by product decision and withdrawn the same day once the product owner learned the
  removal had been approved by the component's author: say WHO approved the current state before proposing to
  reverse it. Both are in `docs/task-management/2026-11-10_offline-followup-proposals.md` section 9.
- **Persistent Playwright profiles hold the previous worker version's caches.** After the worker's source or
  the bundle digest changes, a profile that already installed the old version fails `prepare` on
  `caches.length == 1` before the case under test runs. Delete the profile directories under
  `/tmp/ll-offline-shell-e2e/` for the cases concerned (fresh profiles), do not loosen the assertion.
- **Rails' development log rotates at about 100 MB and keeps one old file.** A long emulator run that logs
  every query loses its earliest request lines. Record the `Started` lines to a separate file as the run goes
  when request counts matter (`log/development.log` → `grep 'Started' >> <scratch>`).
- **A count kept by a queued job reads stale in the request that queued it** (`Board#star` schedules
  `User#remember_starred_board!`). A response that reports such a count is best effort by design; say so in the
  spec with the stale value, rather than making the request write the list itself.
