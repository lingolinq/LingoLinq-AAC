
## Gotcha: a decision modal's result must be checked for SHAPE, not for `=== false` (2026-10-02)

utils/modal.js close(false) REJECTS the open() promise (services/modal.js:355), so a caller's
`if(opts === false)` inside `.then` never runs. Meanwhile anything else resolves as success: the
document-level Escape (utils/raw_events.js:606) calls modal.close() with no argument when focus is
outside the dialog, and a modal opened over another resolves it `{replaced: true}`
(utils/modal.js:136-147). "Make a Copy" callers turned those into a copy with action "nothing", or
reopened the dialog. Fix shape: a predicate on what only the dialog's own buttons produce
(utils/copy_decision.js `is_copy_decision`), checked first in each `.then`. Generalises to any
modal whose resolved value is a decision.

## Gotcha: "no transition happened" must be asserted after the overlay's frame, or at the scheduler (2026-10-02)

utils/view_switch_overlay.js paints on document.body synchronously and starts the transition in a
requestAnimationFrame, so reading a router stub right after the call sees no transition whether or
not the switch went ahead. Record frames and the overlay element (replace rAF for the spec, restore
and remove the overlay in `finally`). A leaked overlay also changes the NEXT call: the "overlay
already up" branch transitions synchronously, so the order of assertions decided red or green.

## Gotcha: new unit tests must not wait on `settled()`; one leaked timer fails them all, then their stubs fail others (2026-10-03)

PR #1094's second CI run failed 23 tests that had passed on the run before, with the same test
order: 13 new tests that `await settled()` each hit the 15s timeout, then all 10 older
`misc Utils all_pages` tests failed. `settled()` waits for every run-loop timer in the app. When an
earlier test leaves the stashes 15-minute flush timer armed (the #1073 mechanism, 2026-09 archive),
it outlives every `settled()`. Whether that happens depends on how earlier tests race, so it is
intermittent. The timed-out organizations-list-load test restored its `Utils.all_pages` stub only
in `finally`, which QUnit never runs after a timeout, so the stub broke every later all_pages test.
Even when green, those tests took ~1.5s each: every test starts with a 1,500ms safety timer from
`stashes.flush` (utils/_stashes.js:210) pending.

Fix shape: wait on the test's own outcome, e.g. `waitUntil(() => c.get('orgs.data') !== undefined)`,
the code's own promise, or two animation frames when the work is synchronous plus one rAF. Restore
globals through `setupRestoreOnTeardown` (tests/helpers/restore-on-teardown.js). To reproduce a
stuck timer locally, schedule `later(() => {}, 20 * 60 * 1000)` from `QUnit.begin` in a scratch copy
of tests/test-helper.js. The old tests then fail exactly as CI did, and the fixed ones pass.
Testem drops the `^` anchor and backslash escapes from long `--filter` regexes, so a CI-order
prefix cannot be selected with one big alternation.

## Gotcha: a compliance doc that restates the privacy policy must say what the policy provides, and when (2026-10-02)

Review of PR #1092 rated present-tense sentences in the consent drafts ("LingoLinq stops ...",

## Gotcha: a one-class `!important` "show" loses to a two-class `!important` "hide"; the org-manager nav vanished at <=550px (2026-10-05)

Organization managers on Modern had NO primary navigation at 550px and below: the pill row was
hidden and the collapsed dropdown never appeared, at any width down to 440px (measured with a
variant of app/frontend/scripts/pillnav-narrow-qa.mjs on home and caseload, Focused and Gentle).
The <=550px block hides `.md-pillnav-dropdown:not(.md-pillnav-dropdown--fit)` at (0,2,0)
!important; the reveal was `.md-pillnav-dropdown--org-menu { display: block !important }` at
(0,1,0). Both important, so specificity decided, and source order (the reveal is later) never
came into it. The <=460px reveal for other users worked only because it also carried a `:not()`.

Fix shape: give the reveal at least the hide's specificity (`.md-pillnav-dropdown.md-pillnav-dropdown--primary`).
When a container rule in a narrower block supplies more than `display` (here `position: relative`,
the anchor for the absolutely positioned option list), a reveal at a WIDER breakpoint has to
restate it. Before trusting any breakpoint swap, measure computed `display` at the edges of each
range rather than reading the cascade: the static read here looked correct.

## Home grid: restyle a card per layout with a CSS-toggled sibling, never layout-conditional markup

Task log: `2026-10-05_focused-single-buttons-badge-action.md`.
The Display Style previews deep-clone the live home grid and only swap its `--layout-*` (and
hero/fullspan) classes (`app/frontend/app/components/display-style.js:474-500`). Markup gated
on `effectiveLayout` therefore leaks into the OTHER layout's preview. To give a card a
different look in one layout, render an always-present sibling and let a layout-scoped CSS
rule pick it, the same pattern as `--caseload-focused` / `--wide-only` / `--narrow-only`.

sheet many rules win only on source order at equal specificity (the <=474px 18px title,
`app.scss` ~68464, beat the 28px caseload title that way). Prove a narrowed rule with a full
computed-style snapshot before/after at every breakpoint, not by reading the cascade. For a
live CDP rule lookup, report `rule.matchingSelectors`, not the first selector of a group.

## SCSS cascade traps in the classic/basic home sheet (2026-10-09)

Task log: `2026-10-09_basic-view-refinements.md`.

**`background` is ONE property, so a tint-only modifier REPLACES the base surface.** A
`.ch-tile--silver` declaring only a tint gradient dropped `.ch-tile`'s white base and rendered
DARKER than the page ground, which is why three successive "make it lighter" passes changed
nothing visible. Lowering the tint's alpha cannot help there — it reveals the card's backdrop,
not white. Layer the tint over an explicit white gradient in the same declaration.

**`_classic-home.scss` orders its media queries 1024 -> 550 -> 900, not monotonically.** A new
`max-width: 900px` block placed by reading order sits BEFORE the existing one and silently loses
every shared property to it. Merge into the existing block. The same inversion already costs the
`<=550px` block most of its rules: the later `<=900px` block re-declares its grid template, the
icon's margin and the button's `justify-self`, so only `justify-items` and `text-align` survive
there. The trap extends to MIXIN APPLICATIONS, not just media queries — a reveal written into
the earlier `min-width: 1025px` block compiles ahead of a mixin applied further down and loses
to it at equal specificity. Fix shape: let the mixin stop deciding, and declare the property at
each call site (nested media query inside the same block) so the variants sit together with
nothing overriding anything.

**`display: contents` is load-bearing and easy to orphan when deleting a media block.** A grid
item's `grid-area` is inert if its PARENT is a normal box; the classic intro card's heading sits
inside `.ch-intro__content` and only becomes placeable because that wrapper is `display: contents`
— declared once, in a DIFFERENT media block from the rules that read it. Grep the single
declaration before deleting any block containing one.

**Reading the SCSS is not enough to know what paints an element; audit the COMPILED CSS.**
`_focused-view.scss` contains blocks with NO `body.ll-layout-focused` scope despite the filename,
serving Basic and Gentle alike. One at `:4465-4488` sets the Actions cards' label `#0F172A` and
description `#0D1B33` at (0,4,0), outranking the `#334155` base (0,1,0) and the `$la-navy` label
rule (0,2,0) — so the title on those cards is not navy, and an "improvement" to `$la-navy` would
have LOWERED contrast (Y 0.0366 vs the incumbent 0.0111). Edits in that file have leaked into
Gentle twice. Verify the selector's scope in the compiled output, not the file it lives in.

**`min-height` with `border-box` is often NOT what sets a rendered height.** On the compact drawer
tile, `min-height: 56px` floors the CONTENT box at 44px while the real stack — tile padding +
inner panel padding + the 44px chip — already reached 68px, so the `min-height` was non-binding
and changing it would have done nothing. Add the box up before picking the property to change.

**Verify the COMPILER's exit status, not the pipe's.** `sass … | tail -4; echo $?` reports
`tail`'s status and will hide a hard "Undefined variable" error behind a green check. Capture
`rc=$?` on the sass invocation itself and assert its output is EMPTY. In zsh, `status` is a
read-only variable — name it something else.

## Routing, handoffs and shared layout constants (2026-10-09)

Task log: `2026-10-09_basic-view-refinements.md`.

- **A subclass that defines a route hook without calling `this._super` silently disables the
  parent's.** `routes/user/home.js:23` defines `afterModel` and never calls super, so
  `routes/index.js#afterModel` does not run on `/:user_name/home` — three of four consumers of
  `_index_login_entry` are unreachable there. Before tracing a parent route's hook, grep the
  child for an override. Two independent reviewers caught a diagnosis that had skipped this.
- **A frontend diff cannot produce an HTTP 500.** A page error was attributed to an in-flight
  Ember change and the change was reverted; the real cause was `ActiveRecord::PendingMigrationError`
  from two unrun migrations. Read the console/network panel first — the status code alone
  partitions frontend from backend. The later 400 "Token needs refresh" on the same page was a
  third, unrelated cause.
- **When two code paths hand off to the same destination, diff them.** `onPickBoard` armed the
  destination's tour before transitioning; `_startHomeAutoOpen`'s handoff only transitioned, so
  the path a newly-registered user actually takes arrived with no tour. Also note WHICH events
  each is bound to: one fired on complete+cancel, the other on complete only, and that difference
  decides whether arming is correct.
- **Shared ordering constants read by two layouts must be DERIVED from, never edited in place.**
  `focusedLayout` and `dashboardLayout` both read the `*_DEFAULT_ORDER` arrays; a Gentle-only
  request re-ordered Focused the first time it was done by editing the constant. The established
  shape is a small pure transform (`editBesideCreate`, now `extrasBesideSpeak`) applied at the
  Gentle-only seams. Cite `app/frontend/app/utils/dashboard_sections.js`.
- **In a positional packer, "these two sit together" must be STATED, not arranged.** Packing fills
  rows from whatever is visible, so the same order yields different pairings per user; naming the
  pair is what makes the guarantee hold for every visibility combination.
- **The ESLint baseline is line- AND column-anchored** (`file|rule|line|column|severity|hash`), so
  ANY inserted line shifts every grandfathered finding below it and reddens `lint:js:ci`. Before
  regenerating (which needs human approval), prove the delta is all shifts: compare each finding
  to the baseline on file+rule+severity+messageHash with line/column dropped. On this branch that
  separated 97 shifts from 1 genuinely new finding, which was then fixed rather than grandfathered.
- **The Modern account rail is mounted in the app shell wrapping the outlet, not per page**, so a
  route gains it by joining `CHROME_ROUTES` regardless of its own markup — `search` has no
  `md-shell` at all. Basic is the opposite: `showGlobalChrome` returns false for it, so each page
  mounts its own `ch-` rail. Check both lists when a page "has no menu".
- **`router.transitionTo('error')` does nothing in this app.** There is no `error` route
  (`router.js:164` is commented out); the call resolves, the URL stays put, and no template
  renders. `error.hbs` appears only as the application error SUBSTATE, when an error BUBBLES.
  `routes/user.js`'s 400/403/404 branches call it and then `return false`, so they silently abort
  the navigation. A whole diagnosis was built on that branch "painting the error page" before
  anyone checked it rendered anything.
- **A UI probe must match text unique to the template it means.** "Failed to load" appears in at
  least nine templates (error.hbs, inline list states in user/index.hbs, available-boards-section,
  board-stats, …). A probe matching the bare string reported the error page when it was a board
  list's own inline failure. Match a sentence only the target renders, and record the route name.
- **A de-dupe guard must key on the state its own action produces, not on a flag with other
  writers.** extras.js skipped `force_logout` when `invalid_token` was set, but sync's
  `check_token(false)` also sets that flag WITHOUT logging out, so after one sync check no logout
  ever fired. Enumerate every writer of the flag before using it as "already handled";
  `logout_under_way` (invalid_token AND NOT isAuthenticated) is the state only the teardown makes.
- **Aging a Device token for a repro needs the Redis cache entry removed too.**
  `Device.check_token` answers from `user_token/<token>` (device.rb:313) before consulting the
  device, so editing `last_timestamp` alone leaves the token valid.
- **`ember test --filter` lowercases the filter string**, so a regex like `/logs out ONCE/`
  silently matches nothing ("No tests matched the filter") against a mixed-case test name. Use
  the `i` flag: `--filter "/logs out once|clears invalid_token/i"`. A `|` in a plain-string filter
  is literal, not alternation.
- **Stub `modal.close` by OUTLET, not by call.** `modal.close_board_preview()` calls
  `modal.close(null, 'board-preview')`, so a stub that flags any call reports the main dialog as
  closed on every route change. A correct fix looked red until the stub checked `outlet`.
- **`.la-wrapper` pages are FIXED full-viewport overlays starting at y=0 under the app header**,
  unlike `.md-shell` pages, which flow below it. Joining a Basic-rail row rule calibrated for
  `.md-shell` (`padding-top: 80px`) put the rail under the header there. Measure: on rail pages
  the rail sits header + 24px (header 70px from 768px up, 114px at <=767px).
- **An early return in a shared function can swallow a caller you did not trace.**
  `force_logout`'s `if(logout_under_way()) return;` looked like a pure de-dupe, but `check_token`
  sets `invalid_token` the line before calling it, so a session with `isAuthenticated` already
  false never logged out. An existing spec caught it; de-dupe at the CALLER (extras.js) instead.

## Modern home, side rail and Compressed View removal (2026-10-10)

Session log: `2026-10-10_modern-home-polish-and-compressed-view-removal.md`.

- **A sticky element inside a padded scroll container is offset from INSIDE that padding.** The
  pill bar (`position: sticky; top: 70px`) inside `#content` (the scroll container, padding-top
  16-26px depending on the page) was drawn at padding + 70, never flush with the navbar, and no
  margin could move it. The offset has to subtract the padding; the padding varies by page, so
  each rule that sets it also sets a custom property (`--ll-content-pad-extra`) the bar reads.
- **REPEATED: layout-conditional markup on the home grid.** An `{{if (is_equal effectiveLayout
  "focused")}}` class on the Extras card broke the Dashboard Design previews, which clone the
  live DOM and switch only the grid's layout class. The 2026-10 entry "Home grid: restyle a card
  per layout with a CSS-toggled sibling" already said so; read it before any home-grid change.
- **The Focused grid is set INLINE with `!important` by `gridLayoutState`.** No stylesheet can
  rearrange it; a layout change belongs in `dashboard_sections.js`. The <=1024px flex order comes
  from `orderIndices`, read off the same areas, so a grid-only rearrangement needs its own
  reading order (`flowAreas`) or it silently reorders small screens too.
- **Removing code from a file that `docs/legal` or `audit-reports` cite by line moves every later
  citation.** `lib/feature_flags.rb` (capability ledger, `:327`) and `app/models/user.rb` (audit
  findings) kept their line numbers by turning each removed block into a note of the same length.
  Grep for `file.rb:[0-9]` citations before deleting lines from a cited file.
- **An import can go at the END of a module** (ES imports are hoisted), which adds a dependency to
  a file with `.eslint-todo` rows without shifting any of them.
- **`top: 100%` on an absolutely positioned pseudo-element is the padding box.** A divider centred
  in the gap below a bordered row was 1px off per border until the border was counted.
- **A wait loop that greps compiled CSS for a comment never matches**: Sass strips comments. It
  sat until its 400s timeout. Poll for a declaration only the new rule contains.
- **The shared `.ll-boards-grid--compact` rule shapes a grid but does not make one.** On the
  Boards page `display: grid` comes from that page's own class; a new container using only the
  compact class was a block, so its columns and gap never applied.
- **Local RSpec stops at `check_all_pending!` when committed migrations were never applied to the
  test database.** `RAILS_ENV=test bin/rails db:migrate` fixes it but rewrites `db/schema.rb` with
  formatting-only differences from the local Postgres; revert that file afterwards.
