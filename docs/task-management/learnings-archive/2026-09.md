# Learnings appended in 2026-09

Append target for lessons distilled this month (see `README.md` for the entry shape).
Entries older than 2026-09-12 live in `LEARNINGS-2026-01_to_2026-09.md`.

- **A registry row that cites another repo's line numbers goes false silently.** The
  approved-reviewer table cited `codex-review.yml` line numbers that stopped resolving the
  same day; the CI gate's status, its required-check membership, and its model pins must be
  re-read from the API and the workflow file before being relied on. Cite
  `.github/codex/README.md`.
- **A workflow can fail on every scheduled run for months with nobody notified.** Both the
  release-PR and aging-digest workflows had 100% failure rates because the failure
  notifier depended on the same broken secret; a workflow's notification path needs its
  own smoke check. Cite `.github/workflows/weekly-release-pr.yml`.
- **A record of a live process cannot enumerate it; stamp one sample and point at the source.**
  The CI record in PR #962's working log listed in-flight runs head by head and went false on
  every completion; four review rounds moved the stale list one artifact further out (record,
  pending note, owner note, PR body) before the fix was structural: one stamped tally, no
  standing sentence with a post-stamp number, dated observations only inside history entries,
  and `gh run list` for the current state. Cite
  `docs/task-management/2026-09-12_render-decommission-closure.md` (rounds 22 to 26).
- **A review loop over a document's own history entries does not converge; stop it by policy.**
  After both reviewers approved the code at round 16, rounds 17 to 30 each found one-clause
  defects in the previous round's entry describing the previous fix. Each fix is new prose and
  so re-reviewable forever. Once the deliverable is approved and the findings are confined to
  the review record, apply the last round's clauses with local checks and record the pass; the
  next reviewer reads the record, not a round 31. Cite the same log (rounds 17 to 30).
- **A guard stricter than what it protects is a new failure mode.** Rounds 8 to 12 of the same
  PR refined a Docker-ignore matcher model in a spec until each refinement flipped a correct case
  to fail-open; the literal exact assertion (bytes pinned, every `!` entry enumerated) is what
  shipped. Cite `spec/initializers/sentry_spec.rb`.
- **A universal about a config branch needs every read site.** "Cloud Run takes the discrete-var
  branch" was true for runtime and false for the image build, CI and docker-compose, which
  render the url branch; the comment now names each reader. Cite `config/database.yml`.
