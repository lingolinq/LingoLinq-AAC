## How to regenerate + publish (human-initiated)

1. After an `/audit-run` (register + citation-check green), regenerate the page body:
   ```
   ruby scripts/compliance-notion-publish.rb
   ```
   Verify it has not drifted from the register: `ruby scripts/compliance-notion-publish.rb --check`.
2. Push the body to the **single** Notion "Compliance & Audit" page in the **Master Inbox**
   (`c09d6a6c6c9c4158b9d2b2686f865249`). **Regenerate in place** - UPDATE the existing page, do
   not create a new page each run:
   - First time only: create ONE page titled "Compliance & Audit (generated)" in the Master
     Inbox, then record its page id below.
   - Every run after: overwrite that page's content with the new body via the Notion MCP
     (`notion-update-page` / replace-content on the recorded page id).

## Hard rules (non-negotiable)

- **One-way only.** Git register -> Notion. Never read Notion back into the register; never treat
  the Notion page as a source of truth. It is stamped "GENERATED - DO NOT EDIT".
- **Human-initiated / human-gated.** No audit or compliance surface sends anything externally on
  its own. A person runs the push. (The generator script never calls Notion.)
- **Never auto-file, never delete.** The page stays in the Master Inbox; the Notion Gardener does
  not move it and no one trashes it. It is regenerated in place.
- **No student/patient data, ever.** The generator publishes headline counts + an open-findings
  table with file:line anchors only - no evidence snippets, no notes, no closed/superseded
  findings. The register itself carries code-only evidence.
- **The Compliance Posture Report stays DRAFT/unattested** until Scot signs. It is linked from the
  page, never embedded, and is not published externally until attested.
